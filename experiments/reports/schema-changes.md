# Schema changes

Additions to the formats in `bob_plan/data-contract.md`. Fields are only added, never removed or renamed. Every record carries `"schema_version": "1"`.

| Date | Stage | File | Field | Type | Meaning |
|---|---|---|---|---|---|
| 2026-11-13 | 01 | `calls.jsonl` | `attempts` | list of objects | One object per HTTP try: `n`, `http_status`, `latency_ms`, `error` (on failure). |
| 2026-11-13 | 01 | `calls.jsonl` | `cached` | bool | The reply came from the disk cache, not from the endpoint. |
| 2026-11-13 | 01 | `calls.jsonl` | `error_type` | string or null | `refusal`, `timeout`, `connection`, `http_<code>` or `parse_failure`. |
| 2026-11-13 | 03b | `calls.jsonl` | `reasoning_text` | string or null | Reasoning text an endpoint returns outside `content`: Ollama's `reasoning` field and vLLM's `reasoning_content`. `null` when the endpoint returns none. Token counts in `usage` are unchanged. |
| 2026-11-13 | 03b | `calls.jsonl`, in each `attempts` object | `timeout_s` | number | The client timeout, in seconds, used for that try. The first try uses 120 s (or the rung's `timeout_s` if that is smaller); later tries use the rung's `timeout_s`. |
| 2026-11-13 | 03b | `results/specs/breaking_changes.csv` | `breaking_err_ops`, `breaking_warn_ops` | int | The ERR and WARN counts of `oasdiff breaking --match-path`, restricted to the paths the tasks use (L1: `/connectivity` and `/retrieve`; L2: `/verify`; L3: `/sessions` and `/sessions/{sessionId}`). The existing columns are unchanged. |
| 2026-11-13 | 03b | `results/specs/breaking_crossed.csv` | `breaking_crossed_ops` | int | The sum of `breaking_err_ops` over the steps from the client version to the server version. |
| 2026-11-13 | 03b | `specs/changes/<api>.yaml` | `reviewed`, `kind_definitions` | date, object | `status` is now `reviewed`; `kind_definitions.changed_meaning` holds the definition that is also in the file header. |
| 2026-11-13 | 03b | `results/specs/prompt_excerpt_sizes.csv` | new file | | Columns `api, version, serialisation, rung, tokens`: size of each prompt excerpt (`specs/excerpts_prompt/`) in tokens, on each rung's own tokenizer, in compact JSON and in YAML. |
| 2026-11-13 | 03b | `config/models.yaml` | `serving`, `enabled_in_main_runs`, `effort_note` | object, bool, string | R1's Ollama environment variables; whether a rung belongs to the main experiments (R5: `false`); R5's effort wording. |
| 2026-11-13 | 04 | `backend.jsonl` | `schema_version`, `clock`, `response_valid`, `response_errors` | string, RFC 3339 string, bool or null, list of strings | The format version; the clock used for the request (`X-Eval-Clock` or the default); whether the response passed validation against the specification (`null` for requests outside the specification); the validation messages. |
| 2026-11-13 | 04b | `backend.jsonl` | `resolved_device` | string or null | The world ID of the device that was used, for example `D07`, or `null`. |
| 2026-11-13 | 04b | `backend.jsonl` | `identifiers_consistent` | bool or null | `true` if every given identifier belongs to that device, `false` if not, `null` if there was no device. |
| 2026-11-13 | 07b | `tasks/<api>/<task_id>.json` | `missing_info_source` | object | `{<field>: "intent_text" or "fact"}`: where the client has the value of each `missing_info` field. `missing_info` itself is redefined: server-version fields that are needed, absent from the native request and not derivable from it; constants fixed by the server interface are excluded. |
| 2026-11-13 | 07b | `tasks/<api>/<task_id>.json` | `expected_refusal` | object or null | `{status, code}` of the backend's refusal of the primary gold call, or `null`. |
| 2026-11-13 | 07b | `tasks/<api>/<task_id>.json` | `refusal_predictable` | bool | `true` only if the server could know from its own interface that the call will be refused; `false` on every instance. |
| 2026-11-13 | 07b | `tasks/<api>/<task_id>.json` | `gold_calls` | list | May hold several acceptable calls (a second identifier for NAI-only intents, a `maxAge` alternative at L2 v0.2.0). `catalogue_breaking_crossed` is now computed per instance. |
| 2026-11-13 | 07b | `tasks/INDEX.csv` | `expected_refusal`, `missing_info` | string | The refusal code (empty if none); the `missing_info` fields joined with `\|`. |
| 2026-11-13 | 07b | `results/tasks/` | `prompt_half_coverage.csv`, `gold_status.csv`, `missing_info_share.csv` | new files | Prompt-half count per kind; gold status distribution; share of main instances with a non-empty `missing_info`. |
| 2026-11-13 | 07b | `sessions.jsonl` | `n_protocol_slips` | int | Count of protocol slips in the session: a server `ask` or `restate` in NLIP-0, a server `execute` before the client confirmed, or a client whose last turn has no `final` object. Each slip is also written to `errors` as `protocol_slip: ...`. |
| 2026-11-13 | 07b | `sessions.jsonl`, in each `plans[]` object | `client_reply` | string or null | The client's action in reply to that plan (`confirm`, `correct`, `abort`) or to that ask (`answer`); `null` if there was no reply. The scorer's `wrong_plans_caught` reads it. |
| 2026-11-13 | 07b | `sessions.jsonl` | `timeout_rerun` | object or null | Set when a session hit the wall-time limit and was re-run once at twice the limit: `{first_session_id, first_limit_s, ...}`. The record is the second run. |
| 2026-11-13 | 07b | `sessions.jsonl` | `termination` | string | `error_harness` now means infrastructure failure only (HTTP, timeout, connection, backend, inline server); parse failures after repair, refusals and replies that break the turn contract are `error_model`. |
| 2026-11-13 | 07b | `sessions.jsonl`, `calls.jsonl` | `session_id` | string | `calls.jsonl` now carries the same `session_id` as `sessions.jsonl` (before, the agents and the session each made their own, so the files could not be joined). |
| 2026-11-13 | 07b | `results/prompts/prompt_sizes.csv` | new columns | | `role, api, version, prompt, chars, chars_min, chars_max, R1..R4`: one row per distinct rendered system prompt (server at the current version; client per client version), tokens per rung from the rung's own tokenizer. Replaces the earlier `*_tokens_approx` file (chars / 3.5). |
| 2026-11-13 | 07b | `results/prompts/time_projection.csv`, `r5_cost.csv` | new files | | Hours per stage and rung (`hours`: stage 01/04b latencies; `hours_scaled`: also scaled by what the R3 smoke run showed); R5's stage 14 cost by tokenizer and output case. |
| 2026-11-13 | 07b | `config/models.yaml` | `session_limit_s` | number | Per rung wall-time limit of one session: 3600 s for R1, 1200 s for R2–R5. A matrix may override it with `wall_time_limit_s`. |
| 2026-11-13 | 07b | `config/runs/*.yaml` | `parts:` | list | A matrix may hold several parts, each with its own `task_filter`, `rungs`, `prompts` and `conditions`. Without `parts` the matrix is one part. `task_filter` accepts `pilot_round` (`A` or `B`), `per_api_limit`, and `client_versions` as a list or as a mapping `api -> list`. A selection that contains round B instances is refused unless the matrix sets `allow_round_b: true`. |
| 2026-11-13 | 07b | agents | conversation history | | The client and server histories are JSON assistant turns after the opening user turn "Begin the session." This changes what the models receive, not the file formats. |
| 2026-11-13 | 07b | `results/stage3/breaking.csv` | `catalogue_breaking_crossed_mean` | number | Mean of the instances' own catalogue counts in that row. `catalogue_breaking_crossed` is now the version's value from `results/specs/catalogue_breaking_crossed.csv`. |
| 2026-11-13 | 07b | `results/stage3/breaking_by_instance.csv` | new file | | Columns `rung, condition, bin, n, successes, rate, ci_low, ci_high`; bins 0, 1-2, 3-5, 6-10, 11+ by the instance's own catalogue count; P2, stage 3 instances. |
| 2026-11-13 | 07b | `results/interaction/effects.csv`, `stage2_effects.csv` | `n_missing_info_tasks`, `asked_when_needed_share` | int, number or null | NLIP sessions on tasks with a non-empty `missing_info`; the share of them in which the server asked about at least one missing field. |
| 2026-11-13 | 07b | `scores.jsonl` | `scorer_version` | string | `1.1.0`. `request_correct` counts only accepted calls, judges refusals by status and code, judges the device by the backend (`resolved_device`, `identifiers_consistent`) or offline, and matches backend records by `seq`. `questions_needed` counts missing fields, once each. |
